# Совет дома: мини-приложение

«Совет дома» объединяет собрания, заявки в службы и сведения о доме внутри MAX. Житель входит по коду дома, подтверждает квартиру, участвует в голосованиях, отправляет заявку и получает сообщения о её обработке. Соседи могут присоединиться к общей заявке.

Проект команды «Слышу Тебя» для трека «Умный город» хакатона MAX. Приложение рассчитано на жителей и собственников квартир, совет дома и управляющие организации.

Этот репозиторий содержит интерфейс. Авторизация, проверка доступа, хранение данных и отправка сообщений находятся в отдельном серверном приложении.

## Основной сценарий

1. Открыть приложение в MAX и ввести код дома.
2. Указать квартиру, имя и отношение к квартире.
3. Подтвердить вступление через debug-кнопку демонстрационной версии.
4. Открыть собрание и проголосовать либо создать заявку с описанием и вложениями.
5. Посмотреть историю заявки и получить сообщение от бота при смене статуса.

Сейчас доступны вход по коду дома, просмотр собраний и опросов, голосование, отметка об участии, создание и просмотр заявок, фильтры, вложения, подписки на заявки соседей, отправка ссылки на заявку, контакты и события дома. Debug-кнопки оставлены для самостоятельной проверки без сотрудника УК.

## Устройство проекта

Стек: Node.js 24, TypeScript, React 19, Vite 7, MAX UI, VKUI, React Router и Zustand. Версии библиотек зафиксированы в `package-lock.json`.

MAX Bridge подключается в `index.html`. При запуске приложение получает `window.WebApp.initData`. HTTP-клиент передаёт это значение серверу в заголовке `Authorization`. Сервер проверяет подпись и доступ к дому.

- `src/Main.tsx`: подключение библиотек интерфейса, маршруты через `HashRouter`, открытие заявки или собрания по ссылке из MAX
- `src/App.tsx`: начальные данные пользователя
- `src/Navigation.tsx`, `src/navigation`: переходы между разделами
- `src/views/Login`: поиск дома и вступление
- `src/views/Meets`: собрания, опросы и голосование
- `src/views/Requests`: список, создание и карточка заявки
- `src/views/HomeInfo`: контакты и сведения о доме
- `src/storage`: состояние интерфейса в Zustand
- `src/components`: общие элементы интерфейса
- `src/bridge`: описание MAX Bridge и кнопка возврата
- `src/api/client.ts`: адрес API и заголовок авторизации
- `src/api/api.ts`: клиент и типы, созданные из OpenAPI
- `scripts/generate-api.mjs`: получение схемы и создание клиента

В разработке Vite направляет запросы `/api` на сервер. В Docker Nginx отдаёт готовые файлы из `dist`. Данные приложения сохраняются на сервере, браузер хранит текущее состояние экранов.

## Окружение и зависимости

Для разработки нужны Node.js 24, npm и работающий API. Для запуска в контейнере нужны Docker Engine и Docker Compose v2. Для авторизации и сообщений нужен доступ к MAX.

При первом запуске создайте `.env`. Существующий файл с настройками не перезаписывайте.

```bash
cp .env.example .env
```

Переменные:

- `VITE_API_PROXY_TARGET`: адрес сервера для запросов `/api` в режиме разработки. По умолчанию `http://localhost:3000`
- `OPENAPI_URL`: полный адрес схемы для создания клиента, например `http://localhost:3000/api/openapi.json`. Нужен для `npm run dev`, `npm run build` и обычной Docker-сборки. При общем локальном запуске не используется
- `VITE_API_BASE_URL`: адрес сервера для браузера, без `/api` в конце. Пустое значение означает тот же домен, с которого открыт интерфейс
- `VITE_MAX_BOT_USERNAME`: имя бота без `@` для ссылок на заявки. По умолчанию `t364_hakaton_max_bot`
- `FRONTEND_BIND_PORT`: порт интерфейса при запуске Docker Compose, по умолчанию `3004`. При необходимости добавьте его в `.env`
- `APP_IMAGE`: имя Docker-образа, по умолчанию `max-hackathon-frontend:local`

Переменные `VITE_*` попадают в код браузера. Токен бота, пароль БД и секрет приёма событий здесь не нужны. Они задаются только на сервере.

Если интерфейс и API размещены на одном домене, оставьте `VITE_API_BASE_URL` пустым и направьте `/api` на сервер API. Если домены разные, укажите адрес API и добавьте адрес интерфейса в серверный `CORS_ORIGINS`.

## Запуск для разработки

Сначала запустите API по инструкции серверного репозитория. Если API запущен через npm на порту `3000`, достаточно значений из `.env.example`. Если через Docker на порту `3003`, измените `VITE_API_PROXY_TARGET` и `OPENAPI_URL` на адреса с этим портом.

```bash
npm ci
npm run dev
```

Интерфейс будет доступен на `http://localhost:5173`. Порт фиксированный: если он занят, Vite завершит запуск с ошибкой.

Перед запуском автоматически выполняется `npm run api:generate`, поэтому API должен отвечать по `OPENAPI_URL` уже в этот момент. Для проверки внутри MAX локальному интерфейсу нужен доступный из MAX HTTPS-адрес, подключённый к боту. Открытие `localhost` само по себе не создаёт MAX-авторизацию.

## Общий запуск через Docker

В репозитории бэкенда находится `docker-compose.yml`, который запускает интерфейс, API, MySQL и миграции. Разместите репозитории `max-hackathon-backend` и `max-hackathon-frontend` рядом. Если путь другой, укажите `FRONTEND_PATH` в `.env` бэкенда.

Создайте `.env` бэкенда из его `.env.example`, если файла ещё нет, и укажите `MAX_BOT_TOKEN`. Из каталога бэкенда выполните:

```bash
docker compose -f docker-compose.yml up -d --build --wait
```

Приложение откроется на `http://localhost:8080`, API на `http://localhost:8080/api`, Swagger на `http://localhost:8080/api/docs`. Порт меняется через `LOCAL_PORT` в `.env` бэкенда.

В этом режиме Nginx сам направляет `/api/` в контейнер сервера. Настраивать `VITE_API_BASE_URL` не нужно. База данных отдельная, параметры серверной БД из `.env` не используются. При первом запуске она пустая: сведения о доме готовятся по инструкции бэкенда.

Общая конфигурация выбирает цель `local` в Dockerfile. Она собирает интерфейс из сохранённого `src/api/api.ts`, без обращения к OpenAPI. Имя бота берётся из `MAX_BOT_USERNAME` в `.env` бэкенда. Для изменения API сначала обновите клиент через `npm run api:generate` и сохраните его в репозитории.

Для полной проверки в MAX нужен публичный HTTPS-адрес, направленный на локальный порт приложения и подключённый к боту. Настройки бота при запуске Compose автоматически не меняются.

Остановка из каталога бэкенда: `docker compose -f docker-compose.yml stop`. Повторный запуск: та же команда `up` выше. Команда `docker compose -f docker-compose.yml down` удаляет контейнеры и сеть, сохраняя БД и вложения. Не добавляйте `-v`, если данные нужны.

## Отдельный запуск интерфейса через Docker

Собственный `compose.yml` этого репозитория содержит только интерфейс и использует цель `production`. API и MySQL запускаются отдельно. Для подключения к командному API можно указать в `.env`:

```dotenv
OPENAPI_URL=https://max-hackathon.kuz.to/api/openapi.json
VITE_API_BASE_URL=https://max-hackathon.kuz.to
FRONTEND_BIND_PORT=3004
```

При таком размещении API должен разрешать адрес открытого интерфейса через `CORS_ORIGINS`. При использовании общего HTTPS-домена с маршрутизацией `/api` оставьте `VITE_API_BASE_URL` пустым.

После настройки запуск выполняется одной командой:

```bash
docker compose up -d --build --wait frontend
```

Интерфейс доступен на `http://localhost:3004`. Внутри контейнера Nginx слушает порт `80`, снаружи опубликован только `127.0.0.1:3004`. Для открытия из MAX нужен внешний HTTPS-адрес.

Во время сборки `OPENAPI_URL` должен быть доступен из Docker. Значение `localhost` означает контейнер сборки, а не компьютер с API. Сервер должен отдавать схему до начала сборки интерфейса.

Текущий `nginx.conf` обслуживает файлы интерфейса и не перенаправляет `/api`. Используйте внешний сервер с маршрутизацией или отдельный `VITE_API_BASE_URL`.

Изменение `VITE_API_BASE_URL` требует пересборки: адрес записывается в файлы интерфейса при сборке. Compose передаёт только `OPENAPI_URL` и `VITE_API_BASE_URL`. Для другого `VITE_MAX_BOT_USERNAME` нужно дополнить параметры Docker-сборки; текущий образ использует имя бота по умолчанию.

## Работа с API

Базовый адрес клиента задаётся без `/api`: этот префикс уже содержится в созданных методах. Например, правильное значение: `https://max-hackathon.kuz.to`.

После изменения серверной схемы обновите клиент:

```bash
npm run api:generate
```

Команда заменяет `src/api/api.ts`. Настройки и дополнительные действия пишутся в других файлах, например в `src/api/client.ts`.

При открытии приложение вызывает `POST /api/init`. Сервер возвращает профиль, дома и заявки на вступление. После одобрения вступления нужно заново получить эти данные; в текущей демонстрации для этого достаточно закрыть и снова открыть приложение.

Ссылки бота могут передавать `startapp=request_<UUID>`, `startapp=meeting_<id>` или `startapp=poll_<id>`. Приложение открывает соответствующую карточку, сервер проверяет право доступа.

## Данные и внешние сервисы

Профиль MAX, членство, квартиры, голоса, заявки и вложения сохраняет API. В интерфейсе нет собственной БД или постоянной копии этих сведений. Перезагрузка получает данные с сервера.

На командном стенде используются заранее подготовленные сведения о доме. Приложение не получает данные из Госуслуг, ГИС ЖКХ, реестра собственников и платёжных систем. Сумма коммунального платежа на экране дома является демонстрационной, оплата не подключена.

Используются MAX Bridge для данных запуска, возврата и отправки ссылки на заявку, API проекта для данных и серверный бот для сообщений. Файлы выбираются средствами браузера и загружаются в API.

Код дома на служебном слайде: `LIG-84-C9`. Для отдельного сервера дом и действующее приглашение нужно подготовить по инструкции серверного репозитория. Интерфейс не создаёт исходные данные. Для проверки подписок нужен второй пользователь MAX в том же доме.

## Порядок проверки

### Присоединение к дому

1. Откройте [бота](https://max.ru/t364_hakaton_max_bot) в MAX, начните диалог и нажмите «Открыть приложение».
2. Выберите «Ввести код дома», введите `LIG-84-C9`, нажмите «Найти дом». Должна появиться карточка дома. Если код истёк, получите актуальный у команды.
3. Нажмите «Это мой дом, продолжить». Укажите квартиру и имя, выберите «Собственник». Для проверки сообщений оставьте уведомления включёнными.
4. Отправьте форму. Должен появиться экран ожидания подтверждения.
5. Нажмите `debug: approve request`, затем закройте и снова откройте приложение. Должны появиться разделы «Собрания», «Заявки» и «Дом».

Отдельные логин и пароль не нужны. При повторном открытии уже подтверждённого пользователя вступать ещё раз не требуется.

### Собрания и опросы

1. Откройте «Собрания» и карточку текущего собрания. Для голосования выберите заочное или очно-заочное собрание, которое уже началось и ещё не завершилось.
2. Нажмите «За», «Против» или «Возд.» у вопроса. Ответ должен сохраниться после повторного открытия. Пока срок не истёк, ответ можно изменить.
3. Откройте опрос и выберите вариант. Он должен оставаться выбранным после повторного открытия.
4. В очном собрании проверьте отметку о планируемом участии. Во вкладке «Прошедшие» доступны завершённые события.

Собрания и опросы подготавливаются через API. Пустой список означает, что для выбранного дома нет подходящих записей. Права на голосование зависят от аудитории события и подтверждения квартиры.

### Создание и обработка заявки

1. Откройте «Заявки», нажмите «Создать заявку».
2. Заполните тему и описание, выберите категорию и место. Для квартиры выберите свою подтверждённую квартиру, для подъезда или двора добавьте уточнение места.
3. Прикрепите JPEG, PNG, WebP или PDF до 10 МБ. Можно добавить не более пяти файлов. Для общего списка включите «Показать соседям».
4. Отправьте форму. Должна открыться карточка с номером, описанием, вложениями и статусом «Отправлена».
5. Проверьте фильтры «Мои», «Все по дому», «Открытые» и «Решённые». Последний включает заявки, ожидающие подтверждения решения, и закрытые заявки.
6. В карточке откройте блок «Дебаг заявки», выберите другой статус, добавьте комментарий и нажмите «Изменить статус». Должны обновиться история и статус, появиться сообщение «Статус обновлён».
7. При включённых уведомлениях бот отправит сообщение со ссылкой на заявку. Повторно откройте карточку и проверьте сохранённые данные.

### Подписка соседа

1. Вторым пользователем MAX пройдите вступление в тот же дом и подтвердите квартиру.
2. Откройте заявку первого пользователя через «Все по дому» или ссылку по кнопке «Поделиться».
3. Нажмите «Присоединиться». Кнопка должна смениться на «Отписаться», число подписчиков увеличится.
4. Измените статус через «Дебаг заявки». При включённых уведомлениях сообщение получат автор и подписчик.

Автор не подписывается на свою заявку. Заявка с выключенным «Показать соседям» отсутствует в общем списке, но доступна подтверждённым жителям этого дома по ссылке.

### Дом и повторный вход

В разделе «Дом» проверьте адрес, контакты и ближайшие события. Эти сведения приходят с API. Значок уведомлений в заголовке списка собраний или заявок меняет общую настройку сообщений бота.

Для повторной проверки регистрации своим пользователем внизу раздела «Дом» оставлена кнопка `delete user`. Она удаляет профиль и связи с домами на сервере. После её использования заново откройте приложение и пройдите вступление. Для обычного повторного входа удалять профиль не нужно.

## Проверки и сборка

```bash
npm run typecheck
npm run lint
npm run format
```

`npm run format` только проверяет оформление. Команда `npm run format:fix` изменяет файлы.

Для подготовки файлов размещения:

```bash
npm run build
npm run preview
```

Сборка автоматически обновляет API-клиент и создаёт каталог `dist`. Сервер предварительного просмотра по умолчанию доступен на `http://localhost:4173`. Он не использует перенаправление `/api` из режима разработки; нужен отдельный адрес API в сборке или внешний сервер с маршрутизацией.

## Остановка отдельного интерфейса и повторный запуск

При работе через npm нажмите `Ctrl+C`. Для повторного запуска выполните `npm run dev`.

Остановить контейнер:

```bash
docker compose stop frontend
```

Запустить снова:

```bash
docker compose start frontend
```

Удалить контейнер проекта:

```bash
docker compose down
```

После этого используйте `docker compose up -d --wait frontend`. Данные дома и заявки останутся на сервере. Для просмотра состояния и журнала используйте `docker compose ps` и `docker compose logs --tail=100 frontend`.

## Ограничения текущей версии

- Рабочий способ вступления: ввод кода дома. Кнопки сканирования QR и входа через Госуслуги пока не подключены
- Формы создания собраний и опросов, раздел управления домом и отдельный экран чатов пока не подключены. Нужные события создаются через API
- Оплата, квитанции, генерация протоколов и бюллетеней, передача инициатив и отчёты УК из презентации пока не реализованы
- Подтверждение решения заявки жителем и возврат на доработку пока недоступны. Статусы меняются через debug-блок
- Голосование предназначено для предварительного сбора мнений; приложение не оформляет юридически значимое ОСС
- Debug-кнопки и методы `/api/debug` без авторизации намеренно оставлены для демонстрации. Они изменяют данные на сервере
- После одобрения вступления нужно заново открыть приложение. На некоторых экранах ошибка запроса может оставить индикатор загрузки без кнопки повтора
- Обычная сборка через `npm run build` и цель `production` требует работающий источник OpenAPI. Общий локальный запуск использует сохранённый API-клиент
- Полный сценарий нужно проверять в мобильном и веб-MAX. Открытие сайта и успешная сборка не заменяют эту проверку
